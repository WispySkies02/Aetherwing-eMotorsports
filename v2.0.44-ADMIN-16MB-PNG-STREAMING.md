# Aetherwing Main Site v2.0.44 — Larger 3D PNG uploads

**Deploy to aetherwing.net only.** Preserve the separate paint.aetherwing.net Paint Booth v88 package. This release builds on v2.0.43 and keeps its Admin tab-22 panel repair.

## What changed
- The Admin 3D Viewer now accepts genuine PNG files from 100 bytes to **16 MiB (16,777,216 bytes)** instead of 4 MiB.
- The upload API enforces the same bound, with 512 KiB Base64 chunks (each POST stays well within Netlify's 6 MB buffered request limit), and removes temporary chunk records after a successful save.
- The **existing** `/api/paint-3d-texture/:hash.png` URL is served by a Netlify *streaming* Web Response from Netlify Blobs. This fixes the former Base64-buffered 6 MB response bottleneck while staying under Netlify's 20 MB streaming cap. No Paint Booth URL or texture-key schema changes.
- Fixed a pre-existing upload/save mismatch: the uploader now sends the returned `textureKey` field expected by the Admin API, so successful uploads are actually attached to the selected paint.
- Paint Admin now confirms the texture exists using Blob metadata instead of fetching the entire file.
- Help text and the control-center version label updated.

## Real-site acceptance test
1. Deploy this ZIP as the **MAIN SITE** only (not the Paint Booth).
2. Open `aetherwing.net/admin/` > `22 · 3D Viewer` and select a test livery with a supported body.
3. Upload an actual flat PNG larger than 4 MiB but <=16 MiB and click **Upload & save 3D**. Confirm success (upload may require dozens of progress steps).
4. Refresh Admin; the paint should retain its assigned body/texture.
5. Open the texture URL shown by the main site’s `/api/paints` registry or inspect the Paint Booth network panel. It must return HTTP 200, `image/png`, and valid full PNG bytes, not a 502/503 or truncated image.
6. Load that paint in `paint.aetherwing.net`, verify its geometry/UV/color and switch between 3D-ready and fallback paints.
7. Also try a PNG over 16 MiB; it must reject with an accurate message **before uploading**.

**Verification boundary:** Code and archive tests are possible offline. Real Netlify Blob storage, authentication, CDN redirects, and streamed HTTP response require testing after deployment. This is not a claim of production verification.
